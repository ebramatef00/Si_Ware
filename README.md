# Freight Rate Prediction

This is my solution to the freight rate take-home. The goal is to predict the posted rate for
12,000 truckloads moving in November and December 2025, using 48,000 labelled loads from January
to October. The brief is in [`assessment.md`](assessment.md), and the original challenge
instructions are in [`CHALLENGE_README.md`](CHALLENGE_README.md).

What I'm submitting:

- `validation_predictions.csv`: a predicted rate for every one of the 12,000 validation loads
- `scorer_results/candidate_december.png`: the December chart, generated by the provided `score.py`
- `reports/Freight_Rate_Prediction_Report.docx`: the write-up (data issues, how I validated, results)
- `LOOM_SCRIPT.md`: my notes for the video walkthrough

## Getting it running

I used Python 3.11, but anything from 3.10 up should work.

```bash
python -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt
```

The data isn't committed to the repo, so drop the four CSVs you sent into `data/`:

```
data/train_test.csv
data/validation.csv
data/validation_predictions_template.csv
data/december_chart_inputs.csv
```

Then:

```bash
python main.py validate    # runs all the backtests and writes reports/validation_*.csv (about 30 min)
python main.py predict     # trains on Jan-Oct, writes validation_predictions.csv and fills in
                           # data/december_chart_inputs.csv (about 4 min)
python score.py --predictions validation_predictions.csv \
                --december-predictions data/december_chart_inputs.csv
python make_report.py      # rebuilds the report and its figures
python -m pytest tests     # unit tests, plus a check that the model recovers known effects
```

`predict` works on its own. `make_report.py` expects `validate`, `predict` and `score.py` to have
run first.

## How I approached it

Distance explains most of a load's price (the correlation is 0.91), so I model the rate per mile,
on a log scale. That way the model can focus on why one mile costs more than another, and effects
like "reefers cost around 12% more" become simple additions.

While exploring the data I found three things that ended up shaping the whole solution.

**`quote_signal` can't be trusted in November and December.** In January, February, March, June and
September it's basically the true rate per mile. In April, May, July and October it runs backwards,
and in August it's random noise. I can't check the validation months against labels, but real rates
always drop as distance grows, so a useful quote should too. In November and December it doesn't:
the quotes look exactly like August's. So I left this column out.

**Rates climb toward the end of every quarter.** About six to eight weeks before a quarter ends,
prices start rising. By the last day they're up roughly 4% for dry vans, 7% for reefers and 10% for
flatbeds, and then they drop back when the new quarter begins. November and December are the end of
Q4, so this matters a lot here.

**`market_index` is useful, but it's easy to misuse.** Day to day, a 1% higher index means about a
0.15% higher rate. But by autumn the index had fallen back to January levels while prices had crept
up about 6%. A tree model sees "low index" and predicts January prices, which is wrong.

I also cleaned up a few data problems:

- About 1.4% of the rates are clearly wrong, somewhere between a fifth and five times what they
  should be. The distances on those rows look normal, so it's the price that's bad. I drop them from
  training.
- Some weights are negative. They look like sign errors, so I take the absolute value and keep a flag.
- Missing weights stay missing (with a flag). Missing market index values get that day's median.
- Eight cities in the validation set never appear in training. That's 12% of the loads. I don't use
  city names as features at all, only coordinates, so new cities still get sensible predictions.
- A few coordinates are clipped to the edge of a bounding box, and distances bottom out at 70 miles.
  Neither breaks anything, but I avoided features like straight-line distance that go haywire on
  those rows.

## The model

The model has two parts, fitted together:

```
log(rate per mile) = boosted trees on what the load is (distance, coordinates, equipment, weight)
                   + a market index term
                   + a quarter-end ramp (different for each equipment type)
                   + a price level for each quarter
```

The trees are good at learning lane-by-lane differences, but they can't extend a pattern into dates
they've never seen. So everything time-related is a simple linear term instead. October is in the
training data and it's the first month of Q4, which means the model already knows Q4's price level.
I don't have to guess at a trend.

## How I validated it

I set up the backtests to look like the real problem. In the real task I train through October,
the first month of Q4, and predict the second and third months. So I did the same thing for earlier
quarters: train through April and predict May and June, then train through July and predict August
and September. I also reran those with eight random cities removed from training, to check how the
model handles places it hasn't seen.

I didn't use a random split. Loads on the same day share the same market conditions, so shuffling
leaks information. With a random split, the simple tree model looked like it had 2.5% error. On
the honest time-based split it was 4.4%.

## Results

Average error (MAPE) across the backtests, leaving out the mislabelled rates.
`reports/validation_summary.csv` has the other metrics too.

| Model | Predicting months 2–3 of a quarter | Cities never seen in training | A new quarter (October) |
|---|---|---|---|
| **My model** | **1.45%** | **1.62%** | **1.51%** |
| Tree model on every column | 4.23% | 4.26% | 3.07% |
| Median by equipment and distance band | 4.92% | 5.21% | 3.67% |
| Median by lane | 5.58% | 5.21% | 3.81% |
| One rate per mile for everything | 9.59% | – | – |

I also removed each piece of the model one at a time to check it was pulling its weight. Error went
up every time: to 2.63% without the quarter level, 2.81% without the quarter-end ramp, 3.04%
without removing the bad rates, and 3.59% without the market index. Adding `quote_signal` back in
made it worse too (2.09%).

The December chart is a 360-mile dry van run from Lexington to Fort Wayne. Predictions go from $831
to $884. They wave up and down each week with the market index, and climb toward December 31st
because that's the end of the quarter.
